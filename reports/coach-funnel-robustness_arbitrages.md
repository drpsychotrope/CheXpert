`/draft-general` 4 refiner cycles. Pre-V0 scan PASS (premises verified, paths corrected — see `_target_exists.json`). All recommended defaults **APPLIED** in the V1 spec; flip any to re-fold. Diminishing returns hit at cycle 3 (cycle 3→4 delta < 10%: only wording polish, no new structural defect).

## Decisions (RESOLVED — defaults applied)

| Q | Question | Options | **Default (applied)** | Rationale |
|---|---|---|---|---|
| **Q-A** | Funnel surfaces (CO20) — where to offer coaching | (a) Onboarding-end offer ONLY · (b) Home/Dashboard rough-patch prompt ONLY · (c) **BOTH, gentle/non-nagging** | **(c) BOTH** | The two surfaces catch different users: Onboarding-end catches the *new* user the moment calibration finishes (they already ran a ladder — momentum); the Home prompt catches the *returning* user after a rough patch. Both must be **dismissible + non-recurring within a cooldown** (no nagging). Onboarding offer = a third button on the `done`/`offer-game` exit ("Want a full coaching read?") next to "Go home"; Home prompt = a single soft card gated on a rough-patch signal. |
| **Q-A2** | Rough-patch signal for the Home prompt | (a) losing streak via `opponentByPool.recent` · (b) `dueReview` overdue · (c) staleness (no recent coach profile) · (d) combination | **(a) losing streak (recent GameOutcome[]), with (c) staleness as the guard** | `opponentByPool[pool].recent` is already persisted (newest-last, capped) — a run of losses is the honest "rough patch" signal, no new state. Guard with staleness (don't prompt if a fresh `coachProfile` exists, e.g. assessed in the last N days) so we never nag someone who just assessed. Pure predicate `shouldOfferCoach(model, now)` — testable, no Date in core. |
| **Q-B** | Mid-assessment resume (CF4) — persistence model | (a) **persist probe progress + resume (mirror activeSession semantics)** · (b) warn-on-exit only · (c) in-memory singleton like activeSession (survives view-swap, lost on reload) | **(a) persist, BUT via the in-memory singleton pattern first; persisted-to-DB only if cheap & additive** | Session.svelte's `activeSession` is **in-memory** (survives the unmount when a trainer launches, lost on full reload) and that is the established, ratified pattern. C8 mirrors it: lift the Coach wizard's `probes`/`themeIdx`/`step` into `app.coachAssessment` (in-memory singleton). This solves the stated bug (navigating away mid-assessment loses everything) with **zero schema change**. Full cross-reload durability (DB-persist) is a **strictly additive optional field** → offered as FOLD-C2 only if it lands without a DB_VERSION bump; otherwise DEFER. **Default = in-memory parity with activeSession** (matches the contrast the prompt itself draws). |
| **Q-C** | Engine-failure message (CF8) — how to surface | (a) **reuse the existing `info` slot** (Coach.svelte:42/234) · (b) a new banner component · (c) a toast | **(a) info slot** | Coach already has `info` ($state, rendered in the game/analysing steps). On `startGame` catch, set `info = t('coach.engineFailed')` ("Couldn't start the engine — assessed puzzles only.") **before** falling through to `finishWithoutGame()`, and carry it into the result so the user sees *why* the game half is missing. Mirrors Onboarding's `engineFailedSkipping` (sibling already does this) — symmetry, no new surface. |
| **Q-D** | Profile export format (CF10) | (a) **JSON via the F5 download pattern now** · (b) printable/PDF · (c) shareable link | **(a) JSON now; printable DEFER** | The app is local-first (no backend → no link). `CoachProfile` is plain structured-clone-safe data → JSON is the honest, lossless, re-importable artifact. Reuse F5's `downloadPgn` Blob/object-URL pattern (generalize to `downloadJson`/`downloadText` if F5 hasn't shipped). Printable/PDF is a *rendering* concern (no print path exists in the tree — greenfield) → DEFER to a later polish PR (§11). Export button lives in the Coach result panel AND Settings "Your data" panel (Settings.svelte:103-108 already groups data actions). |
| **Q-E** | Does CF10 also IMPORT a profile? | (a) export only · (b) export + import | **(a) export only** | Single concern. Import-a-profile reopens schema-version questions (a `CoachProfile` from an older app version) and a consumer (overwrite live profile?) that belongs to a profile-management PR. C8 ships the export half (the stated CF10 scope: "export/share"). Import → §11. |
| **Q-F** | New ADR? | yes / no | **No (default); flag ADR-0059 only if Q-B picks DB-persist** | C8 is additive + UI. Reuse ADR-0045 (coach mode lineage), ADR-0053 (bilingual), ADR-0054/F5 (client-side download primitive). The ONE architectural candidate is CF4 *DB-persisted* resume (a new durable assessment artifact) — if FOLD-C2 is taken, flag **ADR-0059** (0054-0058 reserved/claimed; 0058 = P2 takeback). In-memory resume (the default) needs no ADR. Do not pre-spend a number. |
