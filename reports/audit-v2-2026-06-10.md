## 1. Synthèse exécutive

**Le socle technique tient ce que la remédiation a promis ; les deux territoires neufs — la correction fine du jeu et toute l'UX/UI — concentrent l'essentiel de la dette restante.**

La remédiation v1 a été **réellement livrée** : moteur sérialisé (FIFO + reject-on-terminate + `onerror`), boot/IDB gardés, CSP launcher durcie, repos de persistance, code-splitting (chunk initial **64 ko**), **478 tests verts**, `svelte-check` **0 erreur**, build vert, CI active — tout re-vérifié *en exécution* cette fois (ce que v1 n'avait pas fait). Sur 16 promesses README confrontées au code, **15 tenues, 1 partielle**.

Mais v2 a fait deux choses que v1 ne pouvait pas faire : **jouer et exécuter** plutôt que lire, et **auditer l'UX/UI** (jamais examinée). Résultat : **143 constats retenus** (après vérification adversariale qui a réfuté 4 constats et recalibré 17), dont **4 critiques** et **37 majeurs**. Les critiques touchent la correction du jeu (corruption d'état au roque 960, attribution de couleur erronée à l'import) et le moteur (analyse silencieusement bridée après toute partie) ; l'axe UX/UI, noté pour la première fois, est le plus faible.

### Le jeu fonctionne-t-il ?

**Oui, de bout en bout, et la boucle pédagogique est réellement câblée** (les 9 maillons play→analyse→fuite→puzzle perso→FSRS→session→radar→drill connectent, vérifié). L'app **boote proprement** (console = HMR Vite seul), Home/Play/Settings rendent, tous les contrôles présents (8 cadences + Custom, styles Human-like/Engine, Standard/960, Blancs/Noirs/Aléatoire, rating *par cadence*). Les bugs ADR-0050/0051 restent corrigés.

**Réserves de correction (révélées en jouant) :** undo après un roque 960 corrompt le plateau (atteignable par le take-back coaché) ; un coup de roi 960 légal vers une case de tour libérée est silencieusement rejeté (67,5 % des positions 960 concernées) ; un PGN importé joué côté Noirs est analysé côté Blancs par défaut (corrompt durablement le profil de faiblesses) ; cinq modes bot n'ont pas la garde `moveUci` de `Play`.

### La qualité revendiquée est-elle garantie ?

**Oui, désormais en exécution** : `npm test` → **478 verts** (et non « 376 » — le README est périmé de +102), `npm run check` → **0 erreur / 0 warning** (367 fichiers), `npm run build` → vert, chunk initial **63,96 ko** (gzip 23,9 ko), une vue = un chunk. CI verte sur les 5 derniers runs.

## 2. Constats critiques & convergents (à lire en premier)

### 🔴 Les 4 critiques

**🔴 C-1 — Le moteur reste bridé à l'Elo du bot après *toute* partie → l'analyse, les endgames et l'import tournent en sous-régime, silencieusement** *(B:engine, confirmé)*
`AdaptiveOpponent.applyStrength` met `UCI_LimitStrength=true` ([`AdaptiveOpponent.ts:71`](../src/engine/AdaptiveOpponent.ts:71)) ; l'unique remise à `false` est [`Play.svelte:427`](../src/ui/Play.svelte:427) (dans `analyzePlayed`). `resetVariant()` ne touche **que** `UCI_Chess960`. Le moteur étant un singleton partagé à options persistantes (re-émises à chaque (re)boot), dès qu'on quitte une partie pour ouvrir l'**Analysis board**, un **endgame** (repli moteur) ou un **import/coach post-partie**, l'analyse classe les gaffes et génère les puzzles **à l'Elo réduit du bot** — et `runAnalysis` **persiste** ces compteurs de faiblesse erronés dans IndexedDB. Masqué car la remédiation n'a testé que le chemin `Play→analyzePlayed` (le seul qui remet la pleine force). **Correctif (effort S) :** `setFullStrength()` enqueué dans `resetVariant` (ou par appel), appelé en tête de `AnalysisBoard.analyze` / `Endgames` (repli) / `Import.analyze` / `Coach.finishGame`.

**🔴 C-2 — `undo()` corrompt le plateau après un roque Chess960** *(B:rules, confirmé empiriquement)*
[`ChessGame.ts:213-226`](../src/game/ChessGame.ts:213) `undo()` appelle `chess.undo()`, mais `applyCastle()` reconstruit le FEN via `chess.load()` — qui purge la pile d'undo de chess.js. Donc après un roque 960, `chess.undo()` ne fait **rien** : pièces restées sur les cases de roque, trait non rendu, mais `san960` et le compteur de répétition décrémentés → état durablement désynchronisé. Atteignable par le **take-back du mode coaché** ([`Play.svelte:329`](../src/ui/Play.svelte:329)) dans une partie 960. **Correctif (effort M) :** pile de snapshots (FEN+droits+san) par coup, restaurée dans `undo()` au moins pour les roques ; + tests.

**🔴 C-3 — L'auto-détection de couleur analyse les imports côté Noirs comme des Blancs** *(B:import, sévérité relevée majeur→critique)*
[`pgn.ts:90-95`](../src/analysis/pgn.ts:90) `inferPlayerColor` n'inspecte que l'en-tête Black et retombe sur `'w'` ; le défaut UI (`'auto'` + nom vide → placeholder `'You'`) ne matche jamais un vrai pseudo → `'w'`. Une partie jouée en Noir est analysée du point de vue des Blancs : gaffes/ACPL/motifs **attribués au mauvais camp**, et **persistés** dans trois stores (gameAnalyses, playerModel, puzzles). C'est le **chemin par défaut** d'un PGN externe collé. **Correctif (effort S) :** inspecter aussi l'en-tête White ; à défaut de match, **refuser de deviner** et demander la couleur.

**🔴 C-4 — Aucun coup jouable au clavier sur aucun échiquier (WCAG 2.1.1)** *(C:a11y, confirmé)*
[`Board.svelte`](../src/ui/Board.svelte) n'expose que des canaux pointeur (drag/clic) ; l'hôte `.cg-board-host` n'a ni `tabindex`, ni `role`, ni `keydown`. Jouer, résoudre un puzzle et driller — les parcours **primaires** — sont inaccessibles aux personnes au clavier seul / switch. **Correctif (effort M) :** rendre les cases focusables + navigation flèches/Entrée, ou une saisie SAN/UCI sous l'échiquier réutilisant le parser existant, partagée par tous les appelants via `Board.svelte`.

### Constats convergents (signalés indépendamment par plusieurs agents — signal le plus fort)

- **UI anglaise vs cible française** — signalé par **3 agents** (C:journey-onboard, C:journey-core, C:i18n). Macro-chantier (~316 chaînes UI + générateurs TS + contenu JSON + notation SAN + risque de layout). Agrégé en un seul constat (P2-langue).
- **`confirm()` natifs bloquants** — signalé par **4 agents** (A2:regression, B:engine [acquis], C:a11y, C:interactions). 5 sites ; celui du coach gèle l'horloge rAF. Contredit la doctrine « jamais de modale forcée ».
- **`moveUci` non gardé / garde non propagée** — A1:drift (W6 partiel) ∩ B:rules ∩ B:train : la garde W6 n'a été posée que dans `Play`, pas dans Sparring/Comeback/Endgames/Onboarding/Coach.
- **Échantillon de puzzles borné par le bas** — A2:regression ∩ A1:drift ∩ B:train : `sampleCurated` prend les 700 plus bas de chaque bande → puzzles servis ~130 cp trop faciles, sans variété, sur le chemin d'entraînement central.
- **Radar : axes « n/a » tracés à 50 %** — B:coach ∩ C:ux-journey : PR #21 a rendu les *étiquettes* honnêtes mais le polygone de valeur trace encore les axes non mesurés à l'attendu.
- **`TACTICS_THEMES` non dérivé de la taxonomie unique** — A1:drift ∩ B:invariants : 3ᵉ liste de motifs en dur, non gardée → désync silencieuse à la prochaine extension.

- **W14(a/b) partiels** (mineurs) : routage faiblesse→vue resté à 4 implémentations ; `TACTICS_THEMES` non dérivé de `MOTIF_PRECEDENCE`.

- **Régressions du code le plus jeune** : `runAnalysis` écrit `weaknessCounters` en DB sans rafraîchir `app.model` (clobber) — **mais** `weaknessCounters` s'avère **état mort** (lu par rien, B:loop), ce qui réduit l'impact ; `{#await}` de vue sans `:catch` (écran blanc) ; `applyStrength` hors chaîne de sérialisation.

## 4. Volet B — Chasse fonctionnelle fraîche

- **Moteur (B:engine)** : sérialisation cœur **correcte et testée** ; les problèmes sont aux coutures — C-1 (bridage persistant), `interrupt()` **code mort** alors que la spec analysis-board l'exige (pile-up des recherches), crash/timeout moteur qui **fige** la partie (`status='playing'` sur le trait du bot, sans reprise), aucune vue n'interrompt le moteur partagé à la navigation (blocage head-of-line).
- **Règles (B:rules)** : promo/sous-promo, e.p., pat, matériel, 50-coups, répétition (standard + 960) **corrects et vérifiés** ; deux vrais bugs que les tests manquent — C-2 (undo-roque-960) et le coup de roi 960 légal rejeté ; garde `moveUci` absente dans 5 modes ; `reason:'fiftyMove'` jamais produit → UI « Draw (draw). ».
- **Boucle fermée (B:loop)** : **tous les maillons connectent**, aucun lien mort. Défauts de *qualité* : aucun badge de cartes dues (le seul signal de relance dans une app sans backend), `weaknessCounters` état mort, « Re-analyse » affiche « 0 puzzles créés » faux, puzzles missed-win sans thème drillable.
- **Coach/Insights (B:coach)** : cœurs purs propres + correctif PR #21 honnête à la source ; mais radar trace encore les n/a à 50 %, tendance Opening/Endgame benchmarkée sur 1200 en dur (contredit le radar voisin), caption « one puzzle per motif » périmée (réel : 2).
- **Import/Openings (B:import)** : parsing solide, mais la *glue* UI a 4 majeurs — C-3 (couleur), PGN multi-parties qui jette une erreur cryptique, `gameId` et id de répertoire qui se **collisionnent** (écrasement silencieux).
- **Drills (B:train)** : 2 majeurs — Vision knight/find-all re-comptent le même prompt (corrompt `visionStats` persisté) ; Resign pendant « réfléchit… » est silencieusement annulé dans Comeback/Sparring (garde `Play` non propagée).
- **Invariants (B:invariants)** : source unique W14 **réelle mais incomplète** (4 routeurs parallèles, `TACTICS_THEMES` non gardé) ; pools de rating propres (zéro fuite inter-cadence) ; kinds SRS propres.

## 5. Volet C — Audit UX/UI (axe inédit)

- **Parcours (C:journey)** : onboarding **piégeant** (aucun skip/abandon une fois l'échelle ou la partie lancée ; recharger re-piège), session quotidienne (P2) **indécouvrable** depuis Home, plateau **figé sans message** pendant l'éval de calibration, **navigation sans historique** (pas de retour de contexte après « Explore »/« Drill »), erreurs moteur masquées par « Bot is thinking… » et coloriées en vert.
- **Accessibilité (C:a11y)** : C-4 (clavier) ; **contraste boutons primaires 3,23:1** (< 4,5:1) sur *toutes* les vues ; **aucun focus visible** (1 seule règle `:focus` dans toute l'app) ; `user-scalable=no` ; zéro `prefers-reduced-motion` ; pas de landmark `<nav>` / `aria-current` ; état dynamique (thinking, horloges, résultat) jamais annoncé (`aria-live`).
- **Système visuel (C:visual)** : discipline **couleur** forte (11 tokens), mais **zéro token** d'espacement/rayon/typo → 8 rayons, 12 tailles de police, ~70 styles inline ; `button.ghost` dupliqué **×13**, `.link` ×6 (avec dérive de padding) ; thème clair ~80 % faisable via `prefers-color-scheme` (8 hex en dur bloquent).
- **Interactions (C:interactions)** : **clic-pour-jouer silencieusement mort** sur tous les échiquiers (seul le drag marche ; tap-tap mort au tactile) ; 5 `confirm()` natifs ; **aucun raccourci clavier** (pas de ←/→ en analyse) ; undo/take-back incohérent. Point fort : le **PromotionPicker** est correctement centralisé (orienté par couleur, annulation propre).
- **Langue (C:i18n)** : UI **100 % anglaise** vs cible FR actée — ~316 chaînes UI + maps de libellés coach/metacog + contenu JSON (concepts, 40 ouvertures ECO, 23 finales) + politique SAN à décider + **risque de layout** (FR ~+15-20 %, topbar `nowrap`) + tests verrouillés sur des chaînes EN. ## 9. Remises en cause (acquis confrontés à une évidence nouvelle)

Conformément à la spec (AP-1), les trade-offs documentés (§11/§12 remédiation, ADRs) ne sont **pas** re-signalés comme découvertes. Trois constats *recoupent* un acquis mais apportent une évidence nouvelle qui mérite réexamen — ils ne vont **pas** au backlog frais :

- **`interrupt()` est du code mort** (B:engine, acquis=true) : la sérialisation W1 est un acquis *de sûreté* (anti-cross-talk), mais la spec analysis-board exigeait `interrupt()`+debounce (AP-CHESS-62) qui n'a jamais été câblé → les recherches s'empilent. À rouvrir : soit câbler `interrupt()`, soit acter formellement l'abandon.
- **`confirm()` coaché bloquant** (B:engine, acquis=true) : tracé en §176 de la remédiation comme reporté, mais il **gèle l'horloge rAF** — réexamen justifié par l'impact horloge, pas seulement l'ergonomie.
- **Explorer « book continuations » vide ~80 %** (B:import, acquis=true) : recoupe le trade-off seed→ETL (ADR-0028) ; à laisser tel quel sauf décision d'étendre la fenêtre de continuations.

### Constats réfutés par la vérification adversariale (exclus, à juste titre)

4 constats ont été **réfutés** et écartés : (1) « lang=en = mauvaise prononciation » — pas un défaut *aujourd'hui* (l'UI est anglaise), relève du chantier FR ; (2) « notation SAN anglaise partout » — convention valide, intégrée au chantier FR comme *décision de politique*, pas comme bug ; (3) « le programme coach ré-implémente le routage » — il consomme bien le routeur partagé ; (4) « README "every game named (ECO)" survendu » — recoupe l'acquis seed (ADR-0028).

16 agents en lecture seule (Volet A : drift + régression ; Volet B : moteur, règles, boucle, oracles README, 4 grappes de modules, invariants ; Volet C : 2 parcours, a11y, visuel, i18n, interactions), format de constat commun **ancré `fichier:ligne`**, sortie structurée validée par schéma. **Vérification adversariale** : chaque constat 🔴/🟠 + chaque promesse README partielle/cassée relu par un agent sceptique (défaut = réfuter) → **41 confirmés, 17 recalibrés, 4 réfutés**. **Exécution réelle** (ce que v1 n'avait pas fait) : `npm ci` léger, `npm test` (478 ✓), `npm run check` (0 err), `npm run build` (vert, chunks), app lancée via serveur de dev (boot propre, parcours Home/Play/Settings, mesures de layout/contraste, débordement nav quantifié à 1280 px et 375 px). Scores qualitatifs (santé d'axe), comparables à v1 là où l'axe existait. Aucune modification du code applicatif (lecture seule : seuls `reports/` + le statut de la spec sont écrits).

> Limite assumée : la prise de **screenshots** du preview a échoué (timeout renderer, probablement l'échiquier WASM) ; les constats UX s'appuient sur les snapshots d'accessibilité, l'inspection DOM/CSS via `eval`, et les mesures de layout — preuves textuelles, non visuelles. Le parcours-gameplay complet (jouer une partie entière au clic) n'a pas été automatisé ; la correction des règles est couverte par la suite de 478 tests + relecture ancrée.
